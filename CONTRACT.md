# ECLIPSE game contract

## Version 4: Domains

`DUNGEONS` defines five separate runs. `start(classId, dungeonId)` selects a class and dungeon; `stage` remains the room number (1–5), while `biome` and `zone` remain fixed for the entire run. Dungeon data owns difficulty rank, enemy HP/damage multipliers, boss HP/name, dialogue and three attack patterns. Class selection is followed by mode `dungeon`; keyboard 1–5 selects the destination. Renderer and music use `biome`, never room number, for the theme.

Room 5 has a dedicated boss. `introTime` protects both actors from movement/damage; E/Enter or the skip button calls `finishIntro()`. Pause freezes this timer. Each boss cycles windup → attack → recover with visible hazards or projectile tells, then enrages below 45% HP. `hazards` store delayed, finite-life hitboxes and are cleared on boss death. `boss-intro` is a real HTML overlay synchronized by app.js; the renderer adds cinematic bars and glow.

There are 30 relics: 18 common and four per class. `classId` filters eligible rewards; `rollRelics()` includes an unowned class relic when available. Wrong-class choices are rejected. Warrior relics alter dodge riposte/third hit/heal/cooldowns, archer relics alter arrows/marks/dash speed/piercing, and mage relics alter freeze/meteor/burn/cooldowns. `warriorPose()` supplies shoulder, elbow, wrist and sword angle; the blade is attached to the hand with separate wrist rotation and a supporting hand for greatswords.

Local `/__boss` appends tests/boss-preview.mjs to the normal app for visual QA, and is never part of the deployed dist directory. Native canvas tests resolve the package relative to Node's runtime, with ECLIPSE_CANVAS_PACKAGE as an override.

## Version 3: Resonance

Skill inputs are K / L; J is exclusively basic attack. Player attackDuration provides normalized wind-up / active swing / recovery animation. Melee collision begins after 20% of the swing; arm, hilt and blade move together. castTime/castDuration/castSkill animate class skills. Warrior uses a following cyclone field and a rush finisher; archer projectiles mark enemies (5 seconds, +25% incoming direct damage) and rain prioritizes marks; mage freezes/shatters and leaves an ember field after meteor impact. Enemy frozen/marked timers and impact effect data drive rendering. `impact` events carry heavy/crit/kill for layered audio. `audio.js` exports Soundscape and SCORES, included in both hosted modules and the classic-script offline bundle. User audio preferences persist separately from progression. Native browser score validation lives at local-only /__audio.

## Version 2 additions

`engine.js` exports `CLASSES`, `WEAPONS`, `ZONES` alongside Game and UPGRADE_POOL. `start(classId)` accepts warrior, archer or mage. UI uses additional mode `select` for class selection. Input adds skill1Pressed, skill2Pressed, swapPressed (F). Game holds classDef, zone, fields and effects. Player holds classId, weaponId, weapon, skillCooldowns, skillTimes, rangeScale, skillPower and cooldownScale. Renderer handles all these and exports drawClassPortrait(canvas,id). Enemies have biome 1..5 and slow timers. All three classes share 18 upgrades; projectiles apply weapon effects.

Offline releases are generated by `node scripts/build-offline.mjs`, emit a classic-script single HTML without external dependencies, and must pass tests/render-offline.test.mjs. Hosted and offline versions share identical engine, app and renderer source. Context restoration and bounded high-DPI rendering guard the canvas lifecycle.

Buildless browser ES modules. Canvas world coordinates 1280 x 720. Root owns index.html, style.css, app.js, package/check scripts. engine agent owns dist/engine.js. renderer agent owns dist/renderer.js. No dependency required.

engine.js exports class Game. Constructor `new Game({onEvent:(type,payload)=>{}})`; methods start(), update(dt,input), chooseUpgrade(id), pause(), resume(), restart(); input is `{left,right,jumpPressed,jumpHeld,attackPressed,dashPressed,interactPressed}`. update uses seconds, max 0.033. Game fields always initialized even on title: mode ('title','playing','paused','upgrade','dead','won'), time, runTime, stage (1..5), roomName, kills, currency, bestStage, player, platforms, enemies, projectiles, particles, texts, drops, portal, upgrades (chosen ids), choices (3 upgrade records), shake, flash, boss. mode changes emit onEvent('mode', mode); other events sfx (string), notify (string), room (roomName).

player: {x,y,w:30,h:46,vx,vy,face:1|-1,hp,maxHp,grounded,attackTime,dashTime,dashCooldown,invuln,damage}. Coordinates top-left, vx/vy px/s. platforms [{x,y,w,h,kind:'ground'|'ledge'}]; enemies [{id,x,y,w,h,type:'crawler'|'flyer'|'archer'|'boss',hp,maxHp,face,vx,vy,hitFlash,attackTime,telegraph}]; projectiles [{x,y,vx,vy,r,hostile,color}]; particles [{x,y,vx,vy,life,maxLife,size,color}]; texts [{x,y,text,color,life}]; drops [{x,y,type:'heal'|'shard',value}]; portal {x,y,w,h,active}; boss null or the boss enemy. All arrays contain live objects. World fixed arena edges x 25..1255, bottom 660, camera not needed. Physics uses platforms with one-way ledges. Dead enemies removed. Default title scene has complete attractive terrain and a few posed enemies. Renderer uses game.time for its animation; app loop updates time if not playing if needed.

renderer.js exports class Renderer constructor(canvas), render(game,dt). Handles backing pixel ratio, logical 1280x720, rich procedural vector/pixel painter visuals with no external assets. Draw scenery, platforms, player, enemies, particles, portal, attack effects but NOT HTML HUD/title/upgrades. Palette dark navy, desaturated teal/blue, moon gold, coral/red hero scarf; ruins, trees, mist, glowing grass. Stage-aware atmosphere. Draw detailed small sprites silhouettes with readable shapes. Root owns HTML HUD.

Upgrade record `{id,name,subtitle,description,icon,rarity}`; icon one of 'sword','bolt','heart','wing','flame','gem','shield','moon'. Engine chooses 3 after clearing each combat stage; choosing advances to next room, stage 5 boss win completes. Portal appears on all enemies defeated and E near portal opens upgrades (stage 1..4). Room 5 boss dead opens portal; E completes win. No automatic upgrade interruption. Local storage persistence guarded try/catch. Root owns audio WebAudio via sfx events and owns key/pointer input.
